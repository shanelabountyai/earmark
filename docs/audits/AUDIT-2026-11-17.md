## 2. Method

1. Read the code above end to end, then the invariant tests, and list what each module *claims* against what a test actually asserts.
2. For each suspected gap, write a test that states the correct behaviour and run it. A test that fails proves the gap; a test that passes kills the suspicion (those are listed in §6 so nobody re-walks them).
3. Proven-defect tests live in `tests/defects/AUDIT-2026-11-17.defects.ts`, which `vitest.config.ts` does **not** include (`tests/**/*.test.ts`), so CI's required checks are untouched. Run them with `npx vitest run --config vitest.defects.config.ts`. Each one is written to go green when its defect is fixed, at which point it can move into `tests/invariants/`.
4. No existing test was skipped, deleted or weakened.

Environment limits (see §7): local Postgres was 16, not 17; Prisma's schema engine could not be downloaded, so migrations were applied with `psql` in file order; the sandbox has no IPv6 stack. GitHub CI (Postgres 17, both RLS legs) is the gate.

## 5. Evidence and proposed fix, per finding

Run the proofs: `npx dotenv -e .env.test -e .env.local -- vitest run --config vitest.defects.config.ts` → 19 failed (19), in both RLS modes. Test names start with the finding id.

### A-01 (high) Webhook SSRF filter: IPv6 forms of private IPv4

`checkUrl` (`src/modules/apikeys/webhooks.ts:74-89`) parses with `new URL()`, which rewrites `[::ffff:127.0.0.1]` to `[::ffff:7f00:1]`. `isPrivateAddress` (`:62-68`) only unpacks the dotted form (`/^::ffff:(\d+\.\d+\.\d+\.\d+)$/`), so a URL literal can never match it, and `64:ff9b::/96` (NAT64), `::/96`, `2002::/16` are not considered. `checkUrl('https://[::ffff:169.254.169.254]/…', false)` resolves; the endpoint is saved and the same check passes again at send. The settings page then shows `lastResponseStatus` and `lastError` per delivery, which is an oracle for what answered.

- Exploitability: one form post by an owner or admin of any org. INV-41's own test asserts "https and public only" with three IPv4 cases, which is why it stayed green.
- Impact depends on the host: `https` only, so plain-http metadata services are out of reach, but any https listener on loopback or the private network is reachable, and error text distinguishes open from closed.
- **Not verified:** that the connection actually lands on the IPv4 address. The sandbox has no IPv6 stack (`EAFNOSUPPORT`). On a dual-stack Linux host an IPv4-mapped destination is routed to IPv4; whether Vercel's runtime does this is untested.
- Clones: every clone on v1.6.x that kept `apikeys` (all but footnote, which removed it; boxloop is on v1.2.1). Deployed ones: tradepost, callboard, gavel, ledgerleave.
- Fix (v1.6.4, `security:`): normalise the host to bytes before classifying; treat `::ffff:0:0/96`, `::/96`, `64:ff9b::/96`, `2002::/16` and `2001::/32` by their embedded IPv4; add `fec0::/10`, `ff00::/8`, and IPv4 `192.0.0.0/24`, `198.18.0.0/15`. Later (v1.7.0): pin the resolved address into the connection, which also closes the rebinding window the code already notes.

### A-02 (medium) SSO issuer: no address check

`saveConnection` (`src/modules/sso/settings.ts:42-63`) requires only `https:`. `configFor` (`flow.ts:34-42`) then runs OIDC discovery against it on every start and callback, and openid-client follows the discovery document's `token_endpoint`, `jwks_uri` and `userinfo_endpoint`. `https://169.254.169.254/`, `https://10.0.0.5/…`, `https://[::1]/` and `https://localhost/` are all saved. The response is not shown (errors are logged by name), so it is blind; `/login/sso/start?org=<slug>` lets an anonymous visitor trigger the fetch, 10 times per 15 minutes per IP.

- Clones: any that set `SSO_ENABLED=1` in a deployed environment. **Not verified** which do; `.env.example` leaves it unset.
- **Not verified:** what openid-client does with a discovery document that names private endpoints; inferred from its API, not tested.
- Fix (v1.6.4): move `checkUrl` to core and apply it to the issuer at save and to each discovered endpoint before use.

### A-03 (medium) AI budget: an unpriced call is free

`withBudget` (`src/core/ai/budget.ts:73-79`) calls `costMicros` only after `fn()` returned. For a model with no row in `prices.ts`, `costMicros` throws there: the provider has already billed, no `AiUsage` row is written, and the hold is left to lapse after 15 minutes. `prices.ts:18` says an unpriced call must not "read as free"; because the throw comes after the call, it does. The test runs five calls under a 1¢ cap; all five reach `fn`.

- Trigger: a clone moves to a new model, or passes the dated id the API returns, without a price row. No attacker.
- Clones: earmark and footnote call `withBudget`. Both pass a constant model that is priced today (read in their checkouts), so this is latent there, not live.
- Fix (v1.6.4): take `provider`/`model` up front and price-check before `fn` runs; if pricing still fails afterwards, record the row at `maxCostMicros` instead of throwing.

### A-04 (medium) Webhook endpoint outlives its creator

`onMembershipEnded` (`src/app/org-hooks.ts:25`) revokes the leaver's API keys, on the owner's 2026-11-05 rule that a credential must not outlive access. `WebhookEndpoint` has no `createdById`, so the endpoint an admin pointed at their own server stays `active`, and they hold its signing secret. The test removes the admin, publishes an event, and the sweep posts it to their URL.

- Fix (v1.7.0): add `createdById` (migration), and in `onMembershipEnded` set the leaver's endpoints to `disabled` with a reason an owner sees. Owner decision: disable, or only flag.

### A-05 (medium) Require SSO leaves existing sessions alone

`setRequired` (`settings.ts:76-84`) flips a flag. `refusesLink` is consulted only by `requestLink` and `redeemLink`; `requireOrg` (`src/core/authz/guards.ts:25-41`) never asks how the session was made. A session created by magic link before the switch lasts its 30 days, and so does the one the exempt owner makes inside the 24 hours. The usual reason to require SSO is that deprovisioning at the IdP ends access; here it does not until the session expires. SSO sessions are not re-checked against the IdP either (30 days), which is common but worth writing down.

- Fix: v1.6.4, in `setRequired(true)`: delete the org's members' sessions whose `method` is not `sso`, except the actor's. v1.7.0: a core seam next to `sso-hook.ts` that `requireOrg` asks, so the rule holds at the guard.

### A-06 (medium) Require SSO is per user, and can lock an org out

`refusesLink` (`hooks.ts:20-28`) refuses a magic link to anyone who is a member of *any* SSO-required org. It does not ask whether that person can use the org's IdP. Two consequences, both proven:

1. A contractor invited with an outside address, who owns their own org, gets no sign-in link at all once the inviting org turns the switch on. One tenant's setting removes access to another tenant, and the person cannot sign in to leave.
2. If no owner's address is on a verified domain, then 24 hours after the switch nobody can sign in to turn it off: SSO refuses them (INV-35) and links are refused (INV-36). Recovery is a database edit.

INV-36's own test uses `member@elsewhere.example`, so the off-domain refusal is currently *asserted*, not missed. Earmark already patched around it for guests (its D-32). So the fix needs an owner decision; I did not touch that test.

- Proposed (v1.6.4): refuse a link only to a user whose email domain is one of that org's verified domains; keep off-domain members out of the required org at the guard (A-05) unless exempt; and refuse `setRequired(true)` unless the acting owner has signed in through this connection.

### A-07 (low) Sign-up link slips past INV-36

`redeemLink` (`src/core/auth/link.ts:65-66`) checks `ssoRefusesLink` only `if (row.userId)`. A sign-up token has `userId = null`; the next line upserts by email and returns the existing user's session. If the account appeared and joined an SSO-required org in the token's 15 minutes, the link signs them in. Fix (v1.6.4): resolve the user first, then check.

### A-08 (low) API key after a demotion

`changeRole` revokes invites the demoted person could no longer send (`revokeInvitesBeyond`) but not the keys they made. Admin → member: the key still resolves with `write`. Fix (v1.7.0): a role-change hook beside `onMembershipEnded`, or record it as accepted.

### A-09 (low) Estimate not validated

`withBudget(ctx, f, -1_000_000n, fn)` runs `fn` and writes a negative hold. Fix (v1.6.4): throw on `maxCostMicros <= 0n`; a `CHECK ("costMicros" > 0)` on `AiHold`.

### A-10 to A-14 (low, by code reference)

- **A-10** `downloadExport` has no `assertFresh`, and the route checks only `org.delete`. A day-old owner session can pull an archive that needed a 5-minute-fresh one to request. The audit CSV route calls `auditEvents` with no `take` and writes no audit line. Fix: `assertFresh` on download (or record the decision), cap or stream the CSV, audit `audit.exported`.
- **A-11** INV-30 walks models that have an `orgId` column. `User`, `Session`, `LoginToken`, `RecoveryCode`, `SsoSubject`, `Org`, `RateLimit` and `CapturedMessage` have no policy, so in enforce mode `app_rw` reads every session and token hash; and a clone table that is org-owned through a parent (loanbook's ledger, noted open in CLONES.md) is invisible to both INV-30 and INV-34. `AuditEvent` and `Outbox` take `INSERT … WITH CHECK (true)`. Fix: an invariant that every model is either org-scoped or on a named global list; tighten the insert policy to `orgId IS NULL OR orgId = current`. Enforce clone today: earmark.
- **A-12** The append-only trigger is row-level, and the migration comment says TRUNCATE is left open so tests can reset. With RLS off the runtime role is the table owner. K13 says "enforced in the DB". Fix: a statement-level `BEFORE TRUNCATE` trigger that raises unless a test-only setting is on.
- **A-13** `send` awaits `res.text()` before `.slice(0, 1024)`, so a receiver can stream for 10 s into memory. `deliver` filters unopenable secrets and still posts with a bare `t=` header. `requireApiKey` returns 401 before `hit`, so key guessing and the lookup behind it are unmetered. Fix: read at most 1 KB; fail the delivery when no secret opens; a per-IP limit on 401s.
- **A-14** `verifyDomain` checks `domainVerifiedElsewhere` and then updates, with no partial unique index on `(domain) WHERE verifiedAt IS NOT NULL`; nothing re-reads the TXT record after the first success. Fix: the index, and a re-check on the cron.

## 6. Suspicions tested and cleared

Listed so they are not re-walked.

- Full invariant suite in a tree with all four modules removed: 37 files, 213 passed / 12 skipped. The `modules-removed` job does not run it, but it holds today. Running it there is a cheap addition.
- Full suite in RLS enforce mode locally: 311 passed / 1 skipped.
- Webhook redirects: `redirect: 'manual'`, so a 3xx is a failed delivery, never followed.
- Idempotency claim, fan-out and delivery claim: read for races; single-statement upsert and `FOR UPDATE SKIP LOCKED` hold. Not separately fuzzed.
- SSO state: single-use delete before any check, cookie-bound, hashed; issuer, audience, nonce and signature covered by INV-37.
- Subject linking: a second org cannot assert another issuer's subject (openid-client pins `iss` to the configured issuer), and email linking requires the org's own verified domain.
- Export: cross-org download, secrets in the archive, request rate: covered by INV-34.
- Audit viewer: every read is `orgId`-scoped inside `withOrg`; the actor filter resolves an email globally but an unknown address and another org's user give the same empty page. CSV cells are formula-defused.
- AI budget concurrency: the row lock plus holds is sound; INV-39 covers it.
